Scanning

  1. Act 1 of 6

    Reconnaissance

    Every attack starts with someone looking. Scanners all over the world sweep the internet for anything left exposed: an open port, an old login page, a forgotten server. One of them finds the target.

    scan   203.0.113.7  :22    open
scan   203.0.113.7  :80    open
scan   203.0.113.7  :445   open
scan   203.0.113.7  :3306  filtered
target acquired
  2. Act 2 of 6

    The attempt

    Then they throw everything at it: exploits for known flaws, stolen passwords, malware in an attachment. The only thing between them and the network is the perimeter.

    try    ssh   root / 123456         fail
try    http  /admin, SQL payload   sent
try    smb   known exploit         sent
try    mail  invoice.pdf.exe       sent
thousands of attempts a minute
  3. Act 3 of 6

    FortiGate holds the perimeter

    A Fortinet FortiGate reads every packet against the policy. Ordinary traffic walks through the gate and is inspected on the way. Whatever nothing allows is dropped and logged.

    deny   untrust > dmz  tcp/445  implicit deny
deny   untrust > dmz  tcp/22   implicit deny
block  untrust > dmz  tcp/443  IPS: SQL injection
allow  untrust > dmz  tcp/443  policy: web-01
perimeter holding
  4. Act 4 of 6

    Palo Alto stops the spread

    One gets in and takes a server in the DMZ. It reaches for the rest of the network and runs into the second wall: a Palo Alto Networks firewall that keeps every zone apart and knows which application is talking.

    allow  untrust > dmz  web-browsing  web-01
alert  dmz            web-01 spawned a shell
deny   dmz > trust    ms-ds-smb     interzone-default
deny   dmz > trust    ssh           interzone-default
lateral movement stopped
  5. Act 5 of 6

    Cortex XDR catches what is left

    A firewall cannot see a user opening the wrong file. Cortex XDR watches every endpoint, ties the behaviour to the network logs, isolates the machine and raises one incident instead of a thousand alerts.

    alert   ws-11  winword.exe > powershell.exe
alert   ws-11  encoded command, outbound beacon
stitch  3 alerts > 1 incident, severity high
action  ws-11 isolated from the network
contained
  6. Act 6 of 6

    The report

    Then it gets written down: how they got in, how far they reached, what stopped them, and what to fix so it cannot happen the same way twice. A test or an incident is only finished when the report is.

    entry    exposed admin page on web-01
reached  DMZ only, LAN untouched
stopped  segmentation rule, XDR isolation
fix 1    patch web-01, remove /admin
fix 2    MFA on all remote access
retest   scheduled

Scope

targets   app.example.com

          stop and call on live data

02

Recon and enumeration

Map everything that is exposed: hosts, open ports, services and versions, hidden directories, parameters and login pages. Most of a test is won here.

NmapWiresharkBurp Suite
$ nmap -sC -sV 10.10.14.7        # lab example
PORT      STATE  SERVICE      VERSION
22/tcp    open   ssh          OpenSSH 8.2p1
80/tcp    open   http         Apache httpd 2.4.41
445/tcp   open   netbios-ssn  Samba smbd 4.6.2
3306/tcp  open   mysql        MySQL 5.7.33
# 4 services, a login page and a hidden /admin
03

Exploitation

Prove the weakness is real. On the web that means SQL injection, XSS, SSRF, authentication bypass and broken access control. On the network, vulnerable and misconfigured services.

Burp SuiteMetasploitPython
GET /item?id=7'             500 SQL syntax error
GET /item?id=7 ORDER BY 4   200
GET /item?id=7 ORDER BY 5   500
# 4 columns, input reaches the query unescaped
[!] finding   SQL injection in "id"   High
04

Privilege escalation and lateral movement

Turn a low-privilege foothold into real impact through misconfigurations, weak credentials and the trust between hosts, the same way a real intruder would.

Kali LinuxLinuxMetasploit
www-data@web01:~$ sudo -l
(root) NOPASSWD: /usr/bin/find
root@web01:~# # misconfigured sudo
root@web01:~# ip route
10.10.20.0/24 dev eth1
[!] pivot     web01 to db01 (10.10.20.5)
